# Atlas - 路过 Planning 目录说明

> 本目录用于承载**会持续迭代的规划类文档**，包括景点扩展、城市扩展、地图路线、素材补充、故事资料卡等。
> 它与 `docs/` 的区别是：
> - `docs/` 放稳定的总纲、规范、技术设计、协议与数据模型
> - `planning/` 放滚动更新的内容规划、资料池与阶段性路线图

---

## 1. 目录用途

`planning/` 主要解决以下问题：
- 规划哪些城市 / 区域 / 景点适合接入当前产品模式
- 为现有景点补足故事、NPC 候选、reward 候选、素材方向
- 为 skills / seed / 素材 / 前端展示提供结构化内容输入
- 沉淀逐景点、逐城市、逐区域的长期可维护资料卡

本目录中的文档默认具有以下特点：
- 会持续更新
- 会带优先级、阶段性判断和待确认项
- 不直接视为 shared / API / 数据模型的唯一真相

---

## 2. 子目录说明

### 2.1 根目录
放总规划、路线图、扩展池，如：
- `景点与地图扩展规划.md`
- `城市扩展路线图.md`
- `素材补充总表.md`

### 2.2 `spots/`
放逐景点资料卡。

建议一个景点一份文件：

```text
planning/spots/{spotId}.md
```

每份资料卡建议包含：
- 基础介绍
- 历史 / 典故
- NPC 知识锚候选
- reward / 图鉴轶事候选
- event 趣味点候选
- 素材方向
- 许可待核项

### 2.3 `regions/`
放逐区域 / 城市 / 主题路线资料卡。

建议一个区域一份文件：

```text
planning/regions/{regionId}.md
```

每份资料卡建议包含：
- 区域定位
- 推荐接入顺序
- 头部景点池
- 地图素材方向
- 主题路线建议
- NPC / reward / event 的总体内容线

---

## 3. 文件命名规范

### 3.1 总规划文件
- 使用中文名称，便于策划与业务阅读
- 例如：
  - `景点与地图扩展规划.md`
  - `四川扩展规划.md`

### 3.2 逐景点 / 逐区域资料卡
- 使用**系统内唯一 id** 命名，避免后续改标题导致链接失效
- 例如：
  - `planning/spots/spot_wuhou_shrine.md`
  - `planning/regions/region_chengdu.md`

---

## 4. 与其他目录的边界

### 4.1 与 `docs/` 的边界
- `docs/`：稳定文档
  - 技术方案
  - 协作规范
  - API 协议
  - 数据模型
  - 系统设计
- `planning/`：滚动规划
  - 城市 / 景点扩展
  - 素材与故事池
  - 逐景点资料卡

### 4.2 与 `tasks/` 的边界
- `planning/` 回答“后续做什么、为什么做、素材和故事从哪里来”
- `tasks/` 回答“这次谁来做、具体怎么做、如何验收”

### 4.3 与 `workers/` 的边界
- `workers/` 说明角色边界
- `planning/` 提供内容输入

---

## 5. 更新原则

- 不在本目录直接改 `shared/**`、seed、前后端实现
- 若规划已成熟，需要进入执行，交由架构师拆到 `tasks/`
- 文档中提及的 id、命名建议、优先级只是规划输入，最终以架构师下发任务与代码真相为准

---

## 6. 一句话总则

**`planning/` 是内容与扩展规划层；它服务于 `tasks/` 和实现层，但不直接替代 shared、协议和代码。**
