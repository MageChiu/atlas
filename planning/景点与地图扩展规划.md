**已识别的内容缺口（本规划要解决的）：**

1. **NPC 资产闲置**：`npc_zhugeliang`（诸葛亮）、`npc_foodie_local`（好吃嘴老饕）、`npc_young_traveler`（背包年轻游客）三个 skill 文件已存在，但**没有任何景点的 `npcIds` 引用它们**。最合理的归属：诸葛亮→武侯祠、老饕→锦里/宽窄/春熙路、年轻游客→熊猫基地/春熙路。
2. **dialogueRewards 稀疏**：8 个景点里只有杜甫草堂配了对话奖励，其余 7 个景点的"故事锚 → 奖励"链路是空的。
3. **故事资料分散无沉淀**：目前景点故事只散落在 NPC `knowledge` 与 event `description` 里，没有**逐景点的叙事资料卡**，导致后续 skills/素材/seed 角色每次都要回头补"这个景点到底讲什么"。
4. **素材许可未核对**：现有实景图从 Wikimedia 拉取，正式上线前需逐张核对许可/署名（见素材方案 §4.1 末）。
5. **奖励卡/NPC 头像/动作图标无图**：rewards、`npc/*/avatar.png`、icons 目前全靠前端占位兜底，无正式视觉。

> 说明：本文不直接写 seed。表格中的"建议新增 id"为**给后端/skills 角色的命名建议**，便于落到 seed/skill 文件时保持一致，最终以架构师下发的公共任务为准。

# 第二部分：新城市 / 区域 / 景点扩展规划

## 5. 扩展原则（适配当前产品模式）

新增内容必须满足当前 World→Region→Spot→Action 体验结构，逐项自检：

1. **可探索**：能挂在现有 DAG 下，有清晰的 region 层级与经纬度（geo/geoBounds/mapSize 可定）。
2. **可叙事**：有足够真实可信的历史/文化故事点，能产出 NPC 知识锚与奖励轶事（不编造历史）。
3. **可出 Action**：4 类 Action（check_in/photo/encounter/random_event）至少能成立 2-3 类。
4. **可出 NPC**：有合适的 signature 人物（历史名人/文化符号）或 generic 角色。
5. **素材可得**：有开放图库实景或可出插画底图，许可可核对。
6. **不摊大饼**：优先"深成都 → 扩四川 → 扩国内名城"的收敛路径，不一次铺开放世界。

## 7. 新增内容的标准交付物（每个新城市/景点）

为保证下游角色零返工，每个新景点交付时必须含（本角色产出）：

1. **资料卡**（同第一部分模板）：介绍 / 典故 / 知识锚 / 奖励轶事 / event 趣味点 / 标签 / 素材方向 / 版权待核。
2. **seed 字段建议**：spotId、name/title、tags、coord 区间、geo 经纬度、建议 status 与解锁条件、建议 Action 列表、建议 npcIds、建议 dialogueRewards。
3. **NPC 候选**：signature 人物 + 知识锚要点 + guardrails 提示（给 skills 开发者）。
4. **素材清单**：cover/scene 画面方向、region 底图 geoBounds 草案、reward 卡面方向、来源与许可。
5. **优先级标注**：在城市内排打卡顺序、open/locked 与解锁递进。
