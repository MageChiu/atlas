## 2. 整体开发流程

```
阶段 0：公共部分（串行，所有人对齐基线）
        │  仓库结构 / 数据模型 / API 协议 / 共享类型 / 错误码 / Mock 约定
        ▼
  ┌─────────────── 公共部分完成（基线冻结）───────────────┐
  │                                                       │
  ▼                                                       ▼
阶段 A：后端轨道（并行）                          阶段 B：前端轨道（并行）
  - 服务框架 + DB                                  - App Shell + 状态/请求层
  - 配置/内容接口                                  - World/Region/Spot 场景 + 相机
  - check-in / execute-action                      - Action 面板 + Event/Reward 展示
  - 进度 / 奖励                                    - AI 上传/轮询/结果页
  - AI 上传 / Task / Result                        - 图鉴 / 记录 / 分享页
  │                                                       │
  └────────────────── 阶段 C：联调收口 ───────────────────┘
        主协议对齐 / 错误码 / 一致性 / MVP 闭环验收
```

- **公共部分是强前置依赖**：数据模型与 API 协议未冻结前，前后端不应大规模编码，以免接口漂移、实现分叉。
- **公共部分完成后，前端与后端可完全并行**：前端基于 Mock 推进，后端基于协议实现真实接口，最后阶段 C 联调切换。

## 3. 依赖关系

### 可并行（公共部分完成后）
- 后端服务框架 ↔ 前端 App Shell
- 后端配置模型/接口 ↔ 前端场景骨架（前端走 Mock）
- 后端 AI 任务壳 ↔ 前端 AI 上传/轮询 UI（前端走 Mock）

### 强依赖
- 任何编码 → 依赖 **公共部分**（数据模型 + API 协议 + 共享类型）冻结
- 前端 Action 面板真实联调 → 依赖后端 `actions` 查询与 `execute` 接口
- 前端 AI 结果展示真实联调 → 依赖后端上传与任务接口
- 前端图鉴/记录页真实联调 → 依赖后端资产接口

## 4. 里程碑对齐

| 里程碑 | 轨道 | 目标 |
| --- | --- | --- |
| M1 项目初始化 | 公共 + 各轨道初始化 | 仓库结构、协议冻结、工程可运行 |
| M2 地图与场景骨架 | 前端 / 后端 | World/Region/Spot 跑通（Mock 或真实） |
| M3 Action/Event 闭环 | 前端 / 后端 | Spot 内执行动作并看到结果 |
| M4 AI 图片链路 | 前端 / 后端 | 上传、生成、查询、展示 |
| M5 资产与分享 | 前端 / 后端 | 图鉴、记录、分享页 |
| M6 联调与发布准备 | 联调 | 测试、埋点、优化 |

---

## 5. 优先级

- **P0**：World/Region/Spot 基础链路、check-in/execute-action、Event 展示、AI 上传与任务壳
- **P1**：图鉴、生成记录、分享页、奖励反馈细化
- **P2**：活动开关、动画优化、埋点、扩展 Action 类型

---

## 6. 全局约束（所有轨道遵守）

- 不把景点逻辑写死在页面组件中；事件逻辑不散落在 UI 层。
- 地图层级切换统一由 Scene / Camera 机制管理，不用页面跳转替代。
- 所有内容实体保留配置入口；用户状态与配置实体分离。
- 接口变更前必须先更新 `docs/Atlas-路过-API协议说明.md`。
- 数据结构遵守 `docs/Atlas-路过-数据模型设计.md`，不新增冲突字段。
- 所有 AI 任务必须异步化；关键写操作支持幂等（requestId）。
- 优先保证主闭环可用，再优化视觉与动画细节。
