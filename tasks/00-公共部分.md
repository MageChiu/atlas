# 00 - 公共部分（前置基线）

> **轨道：公共** ｜ **阶段：0（串行，最先完成）** ｜ **依赖：无**
>
> 本阶段是前端与后端并行开发的强前置依赖。**只有公共部分完成并冻结，前后端才进入并行轨道。**
> 目标：固化仓库结构、数据模型、API 协议、共享类型、错误码与 Mock 约定，避免接口漂移与实现分叉。

---

## C1. 仓库结构与工程基线

- [x] **C1.1** 建立 monorepo / 多目录结构，划分 `frontend/`、`backend/`、`shared/`（共享类型与协议）。
- [x] **C1.2** 统一代码规范：TypeScript 配置、ESLint / Prettier、`.editorconfig`、`.gitignore`。
- [x] **C1.3** 约定资源命名与目录规范（地图资源、景点资源、AI 模板资源）。
- [x] **C1.4** 约定环境变量规范（前端 API base、后端 DB/Redis/对象存储配置项命名）。

**验收**：目录结构与规范文件就位，前后端可基于同一基线初始化各自工程。

---

## C2. 共享数据模型（types）

依据 `docs/Atlas-路过-数据模型设计.md`，在 `shared/` 中定义可被前后端共同引用的 TypeScript 类型。

- [x] **C2.1** 内容模型：`Region`、`Spot`、`Action`、`Event`、`Reward`、`AITemplate`。
- [x] **C2.2** 用户状态模型：`UserRegionProgress`、`UserSpotProgress`、`UserActionRecord`、`UserReward`、`UserGeneratedAsset`。
- [x] **C2.3** AI 任务模型：`UploadedImage`、`AITask`、`AITaskResult`。
- [x] **C2.4** 枚举与建模约束统一：字符串主键、状态枚举、扩展字段保留 JSON 能力（`Record<string, any>`）。

**验收**：前后端引用同一份类型定义，字段命名/类型完全一致。

---

## C3. API 协议冻结（contracts）

依据 `docs/Atlas-路过-API协议说明.md`，固化第一版接口协议。

- [x] **C3.1** 通用返回结构：成功 `{ success: true, data }`；错误 `{ success: false, code, message }`。
- [x] **C3.2** 内容接口：`GET /api/world`、`GET /api/regions/{id}`、`GET /api/spots/{id}`、`GET /api/spots/{id}/actions`。
- [x] **C3.3** 行为接口：`POST /api/spots/{id}/check-in`、`POST /api/actions/{id}/execute`（含 `requestId` 幂等约定）。
- [x] **C3.4** AI 接口：`POST /api/uploads/image`、`POST /api/ai/photo-generate`、`GET /api/ai/tasks/{id}`、`GET /api/ai/results/{id}`。
- [x] **C3.5** 用户资产接口：`GET /api/me/collections`、`GET /api/me/generated-assets`、`GET /api/me/achievements`。
- [x] **C3.6** `execute-action` 统一返回结构冻结：`{ actionId, event, reward, aiTask, progress }`。

**验收**：每个接口的请求/响应 schema 明确，前端可据此写 Mock，后端可据此实现。

---

## C4. 错误码与状态枚举

- [x] **C4.1** 统一错误码：`REGION_NOT_OPEN`、`SPOT_NOT_UNLOCKED`、`ACTION_NOT_AVAILABLE`、`ACTION_COOLDOWN`、`UPLOAD_INVALID`、`AI_TASK_FAILED`、`RISK_BLOCKED`。
- [x] **C4.2** 状态枚举对齐：Region `open/coming_soon/hidden`、Spot `open/locked/hidden`、AITask `pending/running/success/failed`。

**验收**：错误码与状态枚举在 `shared/` 中集中定义，前后端共用。

---

## C5. Mock 与种子数据约定

- [x] **C5.1** 约定 Mock 数据格式与位置（前端 Mock 服务 / 后端 seed 数据使用同一份样例 JSON）。
- [x] **C5.2** 提供 1 个 Region + 5~10 个 Spot + 每 Spot 2~4 个 Action 的样例配置（覆盖 `check_in/photo/encounter/random_event`）。
- [x] **C5.3** 提供示例 Event Pool / Reward / AITemplate 样例，供前后端联调使用。

**验收**：前端可用该 Mock 跑通页面，后端可用同份数据 seed 入库，两端结构一致。

---

## C6. 状态流转与层级约定

- [x] **C6.1** 确认地图四层抽象：World → Region → Spot → Event Layer。
- [x] **C6.2** 确认 Action 执行的状态流转图（点击 → 执行 → loading → 结果：Event/Reward/AI 任务）。
- [x] **C6.3** 确认 AI 任务异步流转（提交 → pending → running → success/failed → 结果回写）。

**验收**：层级与状态流转图文档化，作为前后端共同语义基准。

---

## 公共部分出口标准（冻结条件）

- 共享类型、API 协议、错误码、Mock 数据全部就位且一致。
- 仓库结构与工程规范确定。
- 状态流转与层级约定文档化。

> 满足以上条件后，**解锁** [01-后端.md](./01-后端.md) 与 [02-前端.md](./02-前端.md) 并行开发。
