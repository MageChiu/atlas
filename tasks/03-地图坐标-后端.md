## 1. 背景：公共部分已完成的契约（前置已就绪）

`@atlas/shared` 已扩展并构建通过，后端直接复用，**不要重复定义**：

- `Spot` 新增可选字段 `geo?: { lng: number; lat: number }`（WGS84，保留 `coord` 作兜底）。
- `Region` 新增可选字段：
  - `geoBounds?: { west: number; east: number; south: number; north: number }`
  - `mapSize?: { width: number; height: number }`
- seed（`shared/src/seed/dataset.ts`）已为 `region_chengdu` 填好 `geoBounds`/`mapSize`，并为 8 个景点填好 `geo`。

> 类型来源：`shared/src/models/content.ts`（`GeoPoint` / `GeoBounds` / `MapSize` / `Region` / `Spot`）。

## 2. 任务

### TB-1 契约透传验证（主任务）
- [x] 定位区域/内容查询链路：`GET /api/regions/{id}`（及任何返回 `Region` / `Spot` 的接口，如 region 列表、spot 列表）。
- [x] 确认 `region.geoBounds`、`region.mapSize`、`spots[].geo` **原样透传**：
  - 字段来自 seed，`ConfigRepository`/`ContentService` 通常**无需改动**（直接返回 shared 类型对象）。
  - **若存在显式 DTO/手写 mapper**（把 Region/Spot 拷贝成新对象返回），需**补齐这三个新字段映射**，避免被裁剪丢失。
- [x] 检查序列化层（如 class-transformer `@Expose`/`@Exclude`、interceptor）是否会过滤掉未声明字段；如有，放行新字段。

> 核查结论：`ConfigRepository` 直接装入完整 seed 对象，`ContentService` 原样返回，无 DTO/mapper；
> 全局仅 `ResponseInterceptor` 包 `{success,data}`，无 class-transformer 序列化裁剪。**后端无需改代码即满足透传。**

> 验证补充：`/api/world`（regions[].geoBounds/mapSize）、`/api/spots/{id}`（spot.geo + coord 兜底）亦确认透传一致。
