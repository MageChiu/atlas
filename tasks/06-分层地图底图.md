# 06 - 分层地图底图（方案 A 锁定版：地球作为根 Region）

> **已定方案 A**：地球是 DAG 的根 Region `region_earth`（`type: world`），World 层并入统一的 Region 下钻体系，**消除 World 特例**。
> 目标：**每个区域节点都展示本域真实地图**（地球=世界地图、亚洲=亚洲地图、四川=四川地图、成都=成都地图），
> 子节点用自身中心经纬度 `Region.geo` 投影到父底图，落在地理正确位置。复用 03 的 `geoToPixel`/`assertBoundsRatio`，无新公式。
>
> 本文件为**总览/设计锁定**。具体分工见三份独立任务：
> - 公共 → [`06-分层地图-公共部分.md`](./06-分层地图-公共部分.md)（先行）
> - 前端 → [`06-分层地图-前端.md`](./06-分层地图-前端.md)
> - 素材 → [`06-分层地图-素材.md`](./06-分层地图-素材.md)
>
> 上位依据：`docs/Atlas-路过-数据模型设计.md`、03 投影机制、`tasks/04-区域DAG-{前端,后端}.md`、`协作开发规范.md`。

## 1. 现状缺陷
- 只有叶子城市（成都）配了 `geoBounds`+`mapSize`+景点 `geo`，故只有成都层有可投影底图；容器层（亚洲/中国/四川）纯色背景，空泛。
- `Region` 无经纬度字段，子区域无法投影到父底图定位。
- World 层是独立特例（`worldRootRegionIds` 平铺渲染），与 Region 下钻两套逻辑。

## 2. 方案 A 核心（锁定）
- 新增根 Region `region_earth`（`type: 'world'`），配全球 `geoBounds`/`mapSize`/`mapAsset`，`children = [region_asia]`。
- `worldRootRegionIds = ['region_earth']`。
- `Region` 增 `geo?: GeoPoint`（中心/代表点），子节点用它投影到父底图。
- 前端 World 层语义统一为"进入根 Region(地球) 的 detail"，**与 04-前端的区域栈合并**（栈底=region_earth），所有层级统一为 Region 下钻 + Spot。

## 3. 投影机制（复用 03，无新公式）
```
x = (lng - west)  / (east - west)   * mapWidth
y = (north - lat) / (north - south) * mapHeight
```
- 容器层范围大仍用线性投影（**低精度展示，已接受**，不接入真实 GIS）。
- 世界层用等距圆柱(Plate Carrée)：`geoBounds = {-180,180,-90,90}`、底图 2:1（如 2048×1024）；`assertBoundsRatio` 在 latCenter=0 时期望 ratio=2，照常校验。

## 4. 子节点定位优先级（前端统一规则）
```
子.geo + 父.geoBounds/mapSize 投影  →  RegionChildRef.coord  →  索引散布兜底
```

## 5. 执行顺序
1. 公共：`06-分层地图-公共部分.md`（Region.geo / RegionType.World / region_earth / 容器层 bbox 与 geo / 校验）→ 构建通过即解锁前端。
2. 素材：`06-分层地图-素材.md`（世界/亚洲/中国/四川底图就位，回填真实 mapSize）。
3. 前端：`06-分层地图-前端.md`（World 并入区域栈 + 子区域 geo 投影 + 容器层底图渲染）。
4. 验收：逐层下钻每层都显示本域地图，子节点落在地理正确位置；缺底图占位兜底不崩溃。

## 6. 与 04 的关系（重要）
- 04-前端引入了"区域栈 + childRegions 渲染"。本特性把 World 层并入区域栈（栈底 region_earth），**若 04-前端尚未落地，建议与本任务合并实现**；若已落地，则在其基础上把 World 特例替换为 region_earth 根节点。
- 04-后端的 `getWorld` 返回 `worldRootRegionIds` 对应区域 → 现在即返回 `[region_earth]`，**后端无需再改**（透传 geo/geoBounds/mapSize 即可，已支持）。
