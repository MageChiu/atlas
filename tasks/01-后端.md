# 01 - 后端轨道

> **轨道：后端** ｜ **阶段：A（公共部分完成后并行）** ｜ **依赖：[00-公共部分.md](./00-公共部分.md) 冻结**
>
> 技术栈：NestJS / FastAPI + PostgreSQL + Redis + 队列（BullMQ/Celery）+ 对象存储。
> 与 [02-前端.md](./02-前端.md) **并行推进**，最终在阶段 C 联调收口。
>
> **实现说明（本轮）**：采用 NestJS + 内存仓储（从 `@atlas/shared` seed 载入）+ 进程内异步队列（worker 模拟 AI）。
> 零外部依赖即可本地运行与验收；建表项以内存仓储等价实现，结构预留 Postgres/Redis/对象存储切换接口。
> 启动：`npm run build -w @atlas/backend && node backend/dist/main.js`；冒烟：`npm run smoke -w @atlas/backend`。

## B2. 行为逻辑（M3，P0）

- [x] **B2.1** 建表：`user_region_progress`、`user_spot_progress`、`user_action_records`、`user_checkins`、`user_rewards`。（内存仓储 `StateRepository` 等价实现）
- [x] **B2.2** `POST /api/spots/{id}/check-in`：打卡幂等，首次打卡发放奖励、解锁图鉴。
- [x] **B2.3** `POST /api/actions/{id}/execute`：标准流程（登录校验 → Action 校验 → 开放/解锁校验 → 前置/冷却校验 → 写行为记录 → 选事件 → 发奖励/建 AI 任务 → 统一返回）。
- [x] **B2.4** 事件引擎：从 event pool 按权重选取，处理 `onceOnly` 一次性事件。
- [x] **B2.5** 奖励发放：唯一索引/去重保证不重复，可追踪 `sourceType/sourceId`。
- [x] **B2.6** 进度更新：区域探索度、景点访问/动作计数，更新顺序可控。

**验收**：至少一类 Action 能返回 `event` 与 `reward`，打卡与奖励幂等可靠。

## B3. AI 任务（M4，P0 壳 → P1 完整）

- [x] **B3.1** 建表：`uploaded_images`、`ai_tasks`、`ai_task_results`。（内存仓储 `StateRepository` 等价实现）

**验收**：上传 → 提交任务 → 轮询状态 → 获取结果链路跑通（结果可为模拟）。
