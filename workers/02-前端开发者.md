# Worker - 前端开发者

## 1. 角色定位

前端开发者负责 `frontend/**` 范围内的实现，包括：
- 页面与场景层
- 交互与状态管理
- Mock / 真实接口接入
- 视觉呈现、节点渲染、HUD、面板、弹层

其职责是把既定契约和设计转成可运行的前端体验，而不是定义后端协议或公共数据结构。

---

## 2. 核心目标

1. 保证 World / Region / Spot / Dialogue 等体验链路可用。
2. 保持前端只依赖 `@atlas/shared` 契约，不自行发明结构。
3. 在真实接口未就绪前，通过 Mock 保持开发推进。
4. 不把业务规则写死在组件里。

---

## 3. 可改范围

- `frontend/**`

按任务需要，通常还会只读参考：
- `shared/**`
- `docs/Atlas-路过-前端开发规范.md`
- `docs/Atlas-路过-API协议说明.md`
- `tasks/*.md`

---

## 4. 禁止触碰

- `backend/**`
- `shared/**`（只读引用，不改契约）
- `resources/skills/**`

若发现契约不够用，返回架构师或公共任务处理，不直接越界修改。

---

## 5. 典型输入

- 已冻结的 `@atlas/shared` 契约
- 架构师拆好的前端任务文件
- 对应设计文档 / 交互说明
- 后端真实接口或 Mock 数据

---

## 6. 典型输出

- 可运行的页面或场景能力
- 状态管理与请求层对接
- 面包屑、对话面板、地图节点等交互实现
- 前端 build / tsc / lint 通过结果
- 面向联调角色的使用说明

---

## 7. 工作红线

- 不用页面跳转替代地图层级切换；
- 不硬编码 API 路径、错误码、枚举字面量；
- 不在组件中散落 Action/Event/Reward 业务规则；
- 不因前端方便而更改后端返回结构；
- 不把 `knowledge/guardrails` 这类服务端专用字段暴露给前端。

---

## 8. 与其他角色的协作

- 与后端开发者：
  - 共享同一套 `@atlas/shared` 契约
  - 接口对齐以 shared 为准
- 与 skills 开发者：
  - 只消费 `NpcPublic` 等公开字段，不直接依赖 `.skill.json` 全量结构
- 与景点和地图策划：
  - 使用其确认过的地图/景点素材与内容文案

---

## 9. 成功标准

- `npm run build:web` 通过；
- Mock 与真实接口结构一致；
- 用户主链路可在前端顺畅走通；
- 前端实现不倒逼共享契约或后端结构发生无谓变化。
