# Atlas - 路过 Workers 目录说明

> 本目录用于定义各类开发/内容 worker 的**职责边界、可改范围、输入输出与协作方式**。
> 目标：在多 Agent 并行时，先把“谁负责什么、谁不能越界改什么”写清楚，减少重复设计、越界改动和接口漂移。

---

## 1. 角色列表

| 角色 | 文件 | 核心职责 |
| --- | --- | --- |
| 整体架构师 | [01-整体架构师.md](./01-整体架构师.md) | 统一架构决策、冻结边界、拆任务、协调跨端依赖 |
| 前端开发者 | [02-前端开发者.md](./02-前端开发者.md) | 负责 `frontend/**` 的场景、UI、状态与联调接入 |
| 后端开发者 | [03-后端开发者.md](./03-后端开发者.md) | 负责 `backend/**` 的接口、服务编排、配置读取与运行时逻辑 |
| skills 开发者 | [04-skills开发者.md](./04-skills开发者.md) | 负责 `resources/skills/*.skill.json` 的 NPC 内容资产 |
| 景点和地图策划 | [05-景点和地图策划.md](./05-景点和地图策划.md) | 负责城市/景点扩展规划、地图与景点素材、故事资料整理 |

> 说明：当前**不单独拆“公共 / 契约 worker”**。
> 涉及 `shared/**`、协议、数据模型文档的变更，仍由整体架构师统一协调并下发“公共任务”，避免多个角色同时改契约。

---

## 2. 使用原则

### 2.1 先定角色，再拆任务
- 架构师先判断需求落在哪些角色边界内；
- 再按角色拆任务文件，避免一个任务同时要求改前端/后端/skills/素材。

### 2.2 边界外的改动不要偷偷做
- 一个角色只在自己授权范围内改动；
- 若任务需要跨边界，返回架构师重新拆任务或补公共任务；
- 不允许因为“顺手”就改 `shared/**`、协议、seed 或别端实现。

### 2.3 契约仍以现有规范为准
- `docs/Atlas-路过-协作开发规范.md`
- `docs/Atlas-路过-Agent执行入口.md`
- `@atlas/shared`

本目录不替代这些规范，只把**角色级别的执行边界**说清楚。

---

## 3. 角色协作关系

```text
整体架构师
  ├── 前端开发者
  ├── 后端开发者
  ├── skills 开发者
  └── 景点和地图策划
```

- 架构师负责：
  - 判断需求归属
  - 冻结接口和协作方式
  - 在角色之间转交依赖
- 其他角色负责：
  - 在自己的边界内高质量完成任务
  - 输出清晰的交付物和待对接项

---

## 4. 目录设计原则

- 稳定的总纲、规范、技术设计放 `docs/`
- 会持续迭代的内容规划、资料卡、扩展路线放 `planning/`
- 角色文件保持**稳定**，不与单次功能任务强绑定；
- 单个功能的实现任务仍然放在 `tasks/`；
- 角色文件回答的是“这个 worker 一般负责什么”，任务文件回答的是“这次具体做什么”。

---

## 5. 一句话总则

**先用 `workers/` 明确角色边界，再用 `tasks/` 下发具体任务；角色不越界，架构师做协调。**
