# Atlas - 路过 协作开发规范（Agent 执行约束）

> 适用对象：所有参与开发的 Agent（前端 / 后端 / 公共 / 素材 / 联调）。
> 定位：本文件是**跨端协作的强约束文件**，规定"如何协作、如何改契约、何时算完成、谁能动哪些文件"。
> 它**不重复**各端"做什么/怎么做"——那些见各自规范：
> - 前端实现细节 → `docs/Atlas-路过-前端开发规范.md`
> - 后端实现细节 → `docs/Atlas-路过-后端开发规范.md`
> - 阅读顺序 / 分工 / 阶段 → `docs/Atlas-路过-Agent执行入口.md`
> - 素材 → `docs/Atlas-路过-素材资源方案.md`
>
> 出现任何分歧，按第 2 节优先级裁决。**本文件未授权的行为，默认不做。**

---

## 1. 角色与边界

| 角色 | 可改目录 | 禁止触碰 |
| --- | --- | --- |
| 公共 Agent | `shared/**`、`docs/*数据模型*`、`docs/*API协议*` | 各端业务实现 |
| 后端 Agent | `backend/**` | `frontend/**`、`shared/**`（只读引用） |
| 前端 Agent | `frontend/**` | `backend/**`、`shared/**`（只读引用） |
| 素材 Agent | `resources/assets/**`、`scripts/gen-assets.mjs` | 任何 `src` 业务代码 |

铁律：
- **只有公共 Agent 能改 `shared/**` 与协议/数据模型文档。** 前后端对 `@atlas/shared` 一律**只读引用**。
- 跨边界的需求**不要自己越界改**，按第 3 节走契约变更流程或第 7 节升级。

---

## 2. 唯一事实来源与优先级（冲突裁决）

```
@atlas/shared 冻结契约  >  本协作规范  >  各端开发规范  >  技术设计文档  >  个人习惯
```

- `@atlas/shared`（类型 / `ApiRoutes` / 枚举 / `ErrorCode` / `seedDataset`）是**唯一事实来源**。
- 任何"接口/类型/枚举/错误码/种子数据"的认知分歧，**以 `@atlas/shared` 当前代码为准**，不以记忆或旧文档为准。
- 文档与代码冲突时：契约代码为真，文档需被修正（由公共 Agent 同步）。

---

## 3. 契约先行变更流程（最高优先级流程，强制）

任何会影响**对端**的改动（新增/修改字段、路由、枚举、错误码、seed 结构），**必须先改契约，再改实现**。顺序不可颠倒：

```
1. 在 shared/ 修改类型 / 契约 / 枚举 / 错误码 / seedDataset
2. npm run build -w @atlas/shared  通过
3. 同步文档：docs/Atlas-路过-API协议说明.md 和/或 数据模型设计.md
4. 通知/记录对端（在对应 tasks/*.md 标注变更点）
5. 各端再基于新契约改实现
```

禁止：
- ❌ 前端/后端**私自新增对外字段**或本地重声明 `Region/Spot/Action/...`。
- ❌ 硬编码接口路径字符串（必须 `ApiRoutes.*`）、裸枚举字面量（必须用 `@atlas/shared` 枚举常量）。
- ❌ 新增 `ErrorCode` 却不先改 shared 与协议文档。
- ❌ 后端另立返回 DTO 结构替代 shared 契约类型。

> 已冻结、不得擅自变更字段的结构：`ExecuteActionData = { actionId, event, reward, aiTask, progress }`。

## 4. 任务协作流程

### 4.1 任务文件约定
- 任务在 `tasks/` 下维护，按轨道拆分；**交给独立 Agent 的任务文件必须自包含上下文**（背景、契约、源文件路径、验收），使其无需读其他任务文件即可执行。
- 一个跨端特性若拆给多个 Agent，**按端拆成独立文件**（示例：`tasks/03-地图坐标-后端.md` / `tasks/03-地图坐标-前端.md`），并在 `tasks/README.md` 索引。
- 用 `- [ ]` / `- [x]` 跟踪进度；**完成一项立即勾选**，不批量补勾。

### 4.2 并行规则
- **公共部分是强前置**：`shared` 契约未冻结前，前后端不得大规模编码。
- 公共完成后前后端**并行**：前端基于 Mock（`NEXT_PUBLIC_USE_MOCK=true`）推进，后端基于协议实现，最后联调切换。
- Mock 与真实接口**返回结构必须完全一致**（同源 `@atlas/shared` 契约），联调应做到"零字段改动即可联通"。

### 4.3 改动范围纪律
- 只做任务要求的改动；不顺手重构、不加未要求的功能/配置/抽象（见根 `important-instruction-reminders`）。
- 不为不可能发生的场景加防御代码；只在系统边界（用户输入 / 外部接口）做校验。

---

## 5. 工程约定红线（所有 Agent 共守）

- **架构**：地图层级切换只能由 Scene/Camera 驱动，禁止用 `router.push` 替代层级跳转；事件/动作业务规则不写死在组件。
- **模块**：后端模块间只经 Service 协作，禁止跨模块直接访问对方 Repository/表。
- **数据**：配置实体与用户状态实体严格分离；主键统一字符串 ID；状态存枚举字符串；seed 唯一源 `shared/src/seed/dataset.ts`。
- **素材**：素材不打包进任何 `src` 产物；路径只来自 `seedDataset` 字段（`mapAsset/coverAsset/sceneAsset/asset/icon`），组件不拼死路径；缺图走占位兜底；正式上线前核对版权。
- **端口**：禁止硬编码端口。前端 `FRONTEND_PORT`（默认 3000）、后端 `process.env.PORT`（默认 3001）、素材 `ASSET_PORT`（默认 4001）。
- **异步与幂等**：AI 任务一律异步（禁止请求线程内同步等生成）；写接口必须带 `requestId` 幂等。

## 6. 完成定义（DoD）与自检命令

一项任务在满足以下全部条件前**不算完成**：

1. 任务文件中相关 `- [ ]` 全部勾选。
2. 受影响契约/协议/数据模型文档已同步（若涉及契约变更）。
3. 通过对应自检命令（在仓库根目录执行）：

| 改动范围 | 必过自检 |
| --- | --- |
| 公共 `shared` | `npm run build:shared` |
| 后端 | `npm run build:backend` + 后端 `tsc --noEmit` / lint |
| 前端 | `npm run build:web` + 前端 `tsc --noEmit` / lint |
| 跨端联调 | `./run.sh dev` 起素材/前/后端，按任务验收标准实测主链路 |

4. 给出**面向调用方的简短交付说明**（改了什么、对端是否需要跟进、如何验证）。

> 提交前 `lint` + `tsc --noEmit` 必须通过；不提交含密钥的文件；非用户明确要求不创建多余文档。

---

## 7. 冲突与升级路径

遇到下列情况，**停止猜测，按序处理**：

1. 契约与文档/记忆冲突 → 以 `@atlas/shared` 代码为准，必要时请公共 Agent 修文档。
2. 需要改对端边界内的东西 → 不越界，走第 3 节契约流程或在任务文件标注、请对应 Agent 跟进。
3. 任务描述与契约矛盾、或信息不足无法执行 → 不强行 brute force，向用户/上游澄清。
4. 任何接口/数据结构的"新增需求" → 一律先回到 `@atlas/shared` 与协议/数据模型文档对齐，再动手。

---

## 8. 一句话总则

**契约先行、各守边界、改前同步、完成即自检；拿不准就回到 `@atlas/shared` 和协议文档对齐，而不是各自演化。**
